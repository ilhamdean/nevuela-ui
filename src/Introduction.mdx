# Nevuela UI

**Nevuela** is an original, open-source **Vue 3 + TypeScript** component library and design system for
**data-dense applications** — dashboards, record lists, detail pages, and multi-step flows. It suits any
product where people work in tables and forms all day: admin and back-office tools, analytics,
operations software, internal tools.

Its visual language — **Aurora/Nebula** — pairs deep indigo-violet neutrals with an emerald-green
brand accent, clear status colors, comfortable corner radii, and a comfortable data-table rhythm.
The code, tokens, and components here are **entirely original**. Icons come from the open-source
[Lucide](https://lucide.dev) set.

## How it was built

Every color, size, and shadow is a semantic design token — never a raw hex/px value in a component —
defined once in `src/style.css` and documented under **Foundations → Design Tokens**.

## Stack

- **Vue 3** (`<script setup lang="ts">`) + **Vite**, **TypeScript** strict
- **Tailwind CSS v4** (CSS-first) with semantic CSS variables
- **Reka UI** primitives (via the shadcn-vue foundation) for accessible behavior
- **class-variance-authority** + **tailwind-merge** + **clsx** for variants
- **@lucide/vue** icons · **vue-echarts** (Apache ECharts) for charts

## Using a component

```vue
<script setup lang="ts">
import { Button, StatusBadge } from 'nevuela-ui'
</script>

<template>
  <Button variant="primary">New order</Button>
  <StatusBadge status="active" label="Active" />
</template>
```

## What's inside

- **Layout & Nav** — AppShell, Sidebar, TopBar, PageHeader, Breadcrumbs, Tabs, Stepper
- **Data Display** — DataTable, StatusBadge, Avatar, MetricCard, EmptyState, Tooltip, CopyableField,
  ProgressBar
- **Forms** — Button, TextInput, Select, Checkbox, RadioCard, Switch, Textarea, SearchInput, FormField
- **Feedback & Overlays** — Modal, Drawer, Toast, Alert, ConfirmDialog (type-to-confirm), DropdownMenu,
  Popover
- **Charts** — UsageChart (line/area metric graphs), Sparkline

## Accessibility

These are screens people use all day, so accessibility is a first-class concern: keyboard navigation and
focus management come from Reka UI, color is never the only signal (status always carries a text label),
form controls are label-associated, and the Storybook **a11y** addon runs in `error` mode. Start with the
**Layout & Nav → AppShell → Full Application** story to see the whole system working together.
