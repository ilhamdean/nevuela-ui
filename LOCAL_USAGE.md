# Using Nevuela UI in another project (locally)

Nevuela UI is `"private": true` and isn't published to npm, so consuming it from another
project means pointing that project at this repo directly instead of `pnpm add nevuela-ui`.
This guide covers building the library and wiring it into a separate local Vue 3 app.

## 1. Build the library

The package's `exports` point at `dist/` (`dist/index.js`, `dist/index.d.ts`,
`dist/nevuela.css`), which isn't committed — build it first:

```bash
cd /path/to/nevuela-ui
pnpm install
pnpm build      # runs build:lib (vite) + build:types (vue-tsc) -> dist/
```

Re-run `pnpm build` any time you change something here and want the other project to pick
it up.

## 2. Link it into the other project

Pick one:

**Option A — `file:` dependency (recommended for local dev)**

```bash
cd /path/to/other-project
pnpm add file:/path/to/nevuela-ui
```

pnpm symlinks the folder into `node_modules/nevuela-ui`, so rebuilding here (`pnpm build`)
is immediately visible there — just restart the other project's dev server to pick up the
new `dist/`.

**Option B — `pnpm link` (global link, no path in package.json)**

```bash
cd /path/to/nevuela-ui
pnpm link --global

cd /path/to/other-project
pnpm link --global nevuela-ui
```

**Option C — packed tarball (closest to a real npm install)**

```bash
cd /path/to/nevuela-ui
pnpm pack                     # -> nevuela-ui-0.0.0.tgz (respects the "files": ["dist"] allowlist)

cd /path/to/other-project
pnpm add /path/to/nevuela-ui/nevuela-ui-0.0.0.tgz
```

Use this when you want to sanity-check exactly what a real consumer would get (no
symlink, no stray source files), at the cost of re-running `pack` + `add` after every
change instead of just a rebuild.

npm/yarn equivalents work the same way (`npm install file:/path/to/nevuela-ui`,
`npm install /path/to/nevuela-ui/nevuela-ui-0.0.0.tgz`, `yarn link`, etc.).

## 3. Install the peer/runtime dependencies

Nevuela's build externalizes its runtime deps (they're not bundled into `dist/index.js`),
so the consuming project needs them installed too. Match the versions in this repo's
[`package.json`](./package.json):

```bash
pnpm add vue@^3.5.0 reka-ui @lucide/vue class-variance-authority clsx tailwind-merge echarts vue-echarts
```

`tw-animate-css` does **not** need to be installed in the other project — it's only used
while *building* Nevuela's own CSS; the compiled output in `dist/nevuela.css` already has
everything resolved.

## 4. Import the stylesheet (and a font)

`dist/nevuela.css` is a fully compiled Tailwind v4 stylesheet — the consuming project
does **not** need Tailwind CSS installed or configured. Import it once, globally, in your
app's entry point:

```ts
// main.ts
import { createApp } from 'vue'
import 'nevuela-ui/style.css'
import App from './App.vue'

createApp(App).mount('#app')
```

Nevuela's type scale assumes **Inter** (`--font-sans` / `--font-heading` fall back to
Helvetica/Arial otherwise). This repo loads it via `@fontsource-variable/inter`, which is
a devDependency here and won't come along automatically — add it yourself if you want an
exact match:

```bash
pnpm add @fontsource-variable/inter
```

```ts
import '@fontsource-variable/inter'
```

(or load Inter however your project prefers — a `<link>` tag to Google Fonts works too).

## 5. Use components

```vue
<script setup lang="ts">
import { Button } from 'nevuela-ui'
</script>

<template>
  <Button>Primary action</Button>
</template>
```

Everything under [`src/index.ts`](./src/index.ts) is re-exported from the package root —
components, their variant helpers (e.g. `buttonVariants`), and prop types.

## Troubleshooting

- **Components render unstyled** — you forgot to import `nevuela-ui/style.css`, or the
  import runs after other CSS that overrides it.
- **Font looks off (Helvetica/Arial, not Inter)** — install/load Inter yourself (step 4);
  it's not bundled with the library.
- **`Cannot find module 'reka-ui'` (or similar) at runtime** — install the runtime deps
  listed in step 3; they're peer/external, not bundled.
- **Changes here aren't showing up** — with a `file:`/`link:` dependency you must re-run
  `pnpm build` in this repo, then restart the other project's dev server (Vite caches
  pre-bundled deps in `node_modules/.vite`; delete that folder if a restart isn't enough).
- **Type errors on the component props** — make sure `pnpm build` (which runs
  `build:types`) succeeded; `dist/index.d.ts` is generated by `vue-tsc`, not `vite build`.
